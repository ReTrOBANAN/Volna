# Волна — рабочее пространство редакции

Локальная первая версия внутренней системы радио, телевидения и сайта: Django Templates, Django Authentication, SQLite и закрытое файловое хранилище. Основные действия сохраняются в базе данных; публичной регистрации нет.

## Быстрый запуск

Требуется Python 3.12 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -c "import secrets; from pathlib import Path; p=Path('.env'); p.write_text(p.read_text().replace('replace-with-a-random-generated-secret', secrets.token_urlsafe(64)))"
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Windows PowerShell: вместо `source` выполните `.venv\Scripts\Activate.ps1`, вместо `cp` — `Copy-Item .env.example .env`.

Откройте http://127.0.0.1:8000/. Команда `seed_demo` выведет логины и случайные пароли только при первом создании аккаунтов. Сохраните их в менеджере паролей: приложение не хранит открытые пароли и не выводит их повторно. Повторный запуск не дублирует пользователей и демонстрационные записи. Префикс логинов `demo_` зарезервирован для демонстрации: если найден аккаунт с таким логином без правильной роли, команда откажется продолжать и ничего не изменит.

Команда выше записывает случайный секрет в локальный `.env`. При ручной настройке создайте собственный `DJANGO_SECRET_KEY`, включите `DJANGO_DEBUG=True` только для локальной разработки и оставьте разрешёнными локальные адреса. Пример генерации секрета:

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

Не коммитьте `.env`, SQLite, загруженные файлы и пароли. Безопасное значение DEBUG по умолчанию — False. Для публичной установки нужны отдельные настройки HTTPS, cookies, web-сервера и статических файлов; `runserver` предназначен для разработки.

## Первый директор без демоданных

```bash
python manage.py setup_roles
python manage.py create_director --username director --name "Анна Сергеевна Волкова"
```

Команда предложит дважды ввести пароль без отображения в терминале. Вместо ручного пароля можно передать `--generate-password`: случайный пароль будет выведен один раз. Повторно существующий аккаунт команда не изменяет. Директор создаёт и отключает сотрудников на странице «Сотрудники». Главреды создают сотрудников своего направления и не могут назначить руководящую роль.

## Что работает

- Вход и выход, профиль, смена пароля и управление аккаунтами по роли.
- Радио: расписание на 14 дней с переключением периодов, редактированием и удалением смен. Добавляйте эфир кнопкой внутри нужного дня: выберите сотрудника и интервал «От 10:00 до 13:00». К эфиру можно добавить необязательное текстовое примечание до 2000 символов; оно открывается в небольшом окошке по клику на карточку эфира в календаре и предварительном просмотре. Окошко закрывается, когда курсор покидает карточку и примечание; также можно нажать Escape или кликнуть снаружи. С клавиатуры карточка открывается клавишей Enter или пробелом. Эфир всегда проходит в пределах одного дня. Справа в форме показаны сохранённые эфиры на выбранную дату и предварительный вид добавляемого или изменяемого эфира; при смене даты расписание обновляется с сервера. После сохранения сохраняется выбранный период расписания. Чтобы открыть прошлое расписание, выберите дату в поле «Перейти к дате» и нажмите «Показать».
- Студии: отдельные дневные и недельные календари двух студий. Добавляйте бронь внутри выбранного дня студии, указывая дату и время «От»/«До»; для записи через полночь задайте дату окончания. Справа показаны сохранённые брони выбранной студии и текущий черновик с предупреждением о пересечениях в выбранный день; смена даты или студии обновляет расписание с сервера. После сохранения сохраняются период и режим календаря. При сохранении сервер проверяет полный интервал, включая запись на несколько дней, и не допускает пересечения активных броней одной студии; отмена освобождает слот.
- Видеозаписи студий: уведомление инженеров, закрепление инженера и отдельная отметка монтажа после завершения записи.
- ТВ: календарь инфоповодов, подбор сотрудников по ролям, личные статусы оператора и фотографа, история этапов производства.
- Цикл материала: съёмка → загрузка файлов → передача на монтаж → монтаж → утверждение главредом ТВ → публикация редакцией сайта.
- Файлообменник: загрузка, поиск, прикрепление к событию, защищённое скачивание и удаление разрешённых файлов. После передачи на монтаж удалить вложение может только директор; действия записываются в аудит. Прямых публичных media-ссылок нет.
- Предложения продюсера: создание, рассмотрение, автоматическое создание события или брони при одобрении с проверкой конфликтов.
- Уведомления: личный список, отметка прочтения, счётчик и обновление каждые 30 секунд.
- Новости: подготовленная страница будущего источника без фиктивного парсера.

## Проверка разных ролей

`seed_demo` создаёт аккаунты `demo_director`, `demo_radio_chief`, `demo_radio_reporter`, `demo_engineer`, `demo_tv_chief`, `demo_tv_reporter`, `demo_operator`, `demo_photographer`, `demo_editor`, `demo_site_chief`, `demo_site_editor`, `demo_producer`. Пароли каждого аккаунта различаются и генерируются безопасно. Данные с пометкой «ДЕМО» находятся в текущем календарном периоде; их технические `demo_key` отличают их от настоящих записей.

Откройте разные роли в отдельных приватных окнах браузера. Например, корреспондент ТВ создаёт событие и назначает команду, загружает файл после съёмки, передаёт материал монтажёру; назначенный монтажёр завершает монтаж, главред ТВ одобряет, редактор сайта публикует. Продюсер может предложить событие или бронь, но кнопку одобрения получает только уполномоченный руководитель.

Проверки доступа выполняются сервером, включая прямые запросы по URL. Скрытые пункты меню отражают те же права. Неизвестная роль не получает доступ к рабочим действиям; аккаунт без профиля требует настройки директором.

## Принятые решения

- У сотрудника одна основная роль. Django Group с кодом роли и роль в профиле должны совпадать; профиль также хранит подразделение. Роли меняются только через проверенный серверный обработчик.
- Редактирование календаря ТВ доступно главреду ТВ и корреспондентам ТВ; производственные действия корреспондента и монтажёра требуют личного назначения. Директор имеет разрешённые административные действия. Временной статус события вычисляется отдельно и не завершает производство.
- Уведомление монтажёру становится видимым в момент `max(время завершения съёмки + 30 минут, время передачи материалов)`. Отдельный фоновый процесс не требуется: видимость вычисляется запросом уведомлений.
- Принятое допущение: все 12 ролей могут загружать и скачивать общие файлы для внутреннего обмена. Файлы, прикреплённые к событию, дополнительно закрыты от пользователей без доступа к материалам этого события. Редакция сайта получает доступ после одобрения материала. Доступ только к календарю сам по себе не открывает исходники.
- Брони имеют полуоткрытые интервалы: запись 10:00–11:00 совместима с записью 11:00–12:00. Активные записи одной студии не пересекаются; отменённые записи не занимают время. В SQLite короткие критические транзакции используют режим IMMEDIATE, сериализующий записи перед проверкой конфликта.
- Типы файлов проверяются по настраиваемому списку расширений; размер по умолчанию ограничен 100 МБ. Это не антивирусная проверка и не проверка фактического содержимого файла. Файлы отдаются как вложения через защищённый обработчик.
- Календарное время отображается в Asia/Novosibirsk, если в окружении не выбран другой часовой пояс.

## Проверка

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
```

При наличии Node.js можно отдельно проверить предпросмотр эфиров и бронирований, меню действий и окошки примечаний:

```bash
node --test scripts/test_booking_preview.cjs scripts/test_shift_preview.cjs scripts/test_shift_actions.cjs scripts/test_shift_notes.cjs
```

Для запуска самого приложения Node.js не требуется.

Тесты покрывают вход, запрет анонимного доступа, ограничения ролей и назначения сотрудников, конфликтующие брони, права на файлы и предложения, этапы производства, историю и уведомления. Тестовая база создаётся отдельно от рабочей.

## Git и версии

Репозиторий: [ReTrOBANAN/Volna](https://github.com/ReTrOBANAN/Volna). Основная ветка — `main`, начальный проверенный снимок — тег `v0.1.0`.

После законченного изменения проверьте список и содержимое правок, затем сохраните их в коммит и отправьте на GitHub:

```bash
git status
git diff
git add -A
git commit -m "Краткое описание изменения"
git push origin main
```

История версий: `git log --oneline --decorate -10`. Чтобы посмотреть начальную версию в отдельной ветке, сначала зафиксируйте текущие правки, затем выполните:

```bash
git switch -c inspect-v0.1.0 v0.1.0
# После просмотра вернуться к основной версии:
git switch main
```

Для отмены конкретного последующего изменения в `main` используйте новый отменяющий коммит. Замените `HASH` хешем нужного более позднего коммита из истории; это не должен быть исходный снимок `v0.1.0`:

```bash
git revert --no-edit HASH
git push origin main
```

Git хранит код и миграции. Файлы `.env`, `db.sqlite3` и `private_media/` в репозиторий не входят: их резервные копии храните отдельно и приватно. Переключение версии кода не меняет уже применённую схему базы. Перед возвратом к версии с другой схемой сохраните согласованную копию базы и загруженных файлов и определите, какие миграции этой версии нужны.

## Структура

`config/` — настройки и корневые URL; `newsroom/models.py` — сущности; `permissions.py` — централизованные права; `services.py` — изменения с транзакциями и проверками; `forms.py`/`views.py` — HTTP-обработчики; `templates/`/`static/` — русский адаптивный интерфейс; `newsroom/management/commands/` — первоначальная настройка и демоданные.

## Ограничения MVP

Сборка предназначена для локальной работы и пилотного тестирования. SQLite имеет ограничения параллельной записи. Для полноценной редакции потребуется PostgreSQL и отдельное приватное файловое/объектное хранилище с поддержкой больших видео, резервным копированием и антивирусной проверкой. Файлы MVP хранятся локально; сохраняйте вместе базу и каталог хранилища. Автоматического удаления архивных файлов и фоновых заданий нет.

Следующая версия: внешняя лента новостей после выбора источника, расширенный поиск и аудит, большие файлы и возобновляемые загрузки, производственная конфигурация и мониторинг. Мобильное приложение, боты, push и интеграции календарей в эту версию не входят.

Технические справочники: [транзакции SQLite в Django](https://docs.djangoproject.com/en/5.2/ref/databases/#sqlite-notes), [защищённая выдача через FileResponse](https://docs.djangoproject.com/en/5.2/ref/request-response/#fileresponse-objects).
